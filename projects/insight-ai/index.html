30 秒摘要

Insight AI 不只替用户判断一条健康信息，而是把证据解释、短时练习和能力回顾连成一条产品链路，帮助用户逐步形成可迁移的判断方法。

产品流程

  1. 01
    输入说法

    用户提交健康说法或内容片段。

  2. 02
    初始判断

    先记录可信度判断、依据与信心。

  3. 03
    检索证据

    从可信资料中召回可追溯证据。

  4. 04
    反馈推理

    指出已关注和遗漏的判断线索。

  5. 05
    迁移练习

    在新情境中再次应用同一种方法。

  6. 06
    更新画像

    记录薄弱维度并形成复习建议。

04

两个关键决策

01

把一次真假回答升级为判断能力训练

为什么这样选
用户真正需要的是理解证据并处理下一条相似内容，而不只是获得眼前结论。
没有选择
只提供结论、引用来源和一段解释
取舍
训练链路更长，需要控制首轮任务负担，并继续验证用户是否愿意完成练习。
02

让用户看到连续任务，而不是多层 Agent 架构

为什么这样选
Understanding、Retrieval、Reasoning 与 Reflection 是后台能力，前台应围绕判断、反馈和练习组织体验。
没有选择
按 Agent 节点展示系统处理过程
取舍
技术结构的可见度降低，但用户更容易理解当前任务和下一步行动。
05

一个 Bad Case

答案正确，但方法没有留下

现象
用户接受了真假结论，却说不清证据为什么可靠，遇到下一条相似内容时仍要重新依赖 AI。
诊断
单轮回答解决了当前信息，却没有要求用户表达依据，也没有通过新情境检查方法迁移。
处理
在证据反馈后加入一则短时迁移练习，并用薄弱维度决定提示强度和后续复习。
结果
完整训练闭环和验证框架已经形成；真实用户是否获得稳定迁移能力仍在验证。

项目概述

用户刷到“某种保健品能预防疾病”或“一个偏方三天见效”时，通常只想快速知道能不能信。普通 AI 可以直接给出结论，却很少告诉用户该看哪些证据、哪一步推理有问题，以及下次遇到类似内容怎么办。Insight AI 是一个面向健康信息判断场景的 AI 产品：它既能帮助用户核查眼前的说法，也能把判断过程转化为短时练习，让用户逐步掌握可重复使用的方法。项目由我独立负责产品定位、需求分析、核心功能、Agent 工作流、原型方案和效果验证设计。

痛点机会

目标用户是经常从社交媒体获取健康知识、关注健康但缺少专业背景的普通用户。他们面临三个连续问题：第一，不知道一条信息是否值得相信；第二，即使看到结论，也分不清来源、证据和推理哪里可靠；第三，面对下一条相似信息时仍要重新依赖别人判断。传统辟谣和通用问答往往只解决第一步，并采用同一种解释方式，忽略了有些用户容易被“专家背书”影响，有些用户则更容易被情绪、数据表达或因果故事说服。产品机会是把一次回答升级为“核查当下内容 + 练习判断方法 + 记录个人薄弱点”的连续体验。

目标指标

产品目标分为三层。即时价值：帮助用户更快完成健康信息可信度判断，并看懂证据来源；能力价值：让用户能够说出自己的判断依据，并把方法应用到未见过的新内容；长期价值：记录用户容易忽略的判断维度，提供适合其水平的练习和复习。产品效果将关注真假判断准确率、判断依据完整度、分享意愿、判断信心和后续练习完成情况。当前这些指标用于指导产品验证，不代表已经取得量化提升。

用户调研

用户真正要完成的任务不是“替我判断这一条是真是假”，而是“当我看到一条健康信息时，快速判断它是否可信，并知道下一步该如何验证”。沿着这一任务，我把用户常见的判断困难归纳为五类：来源与资质、证据质量、因果推理、数据表达、情绪与风险框架。产品体验需要做到两点：一是在用户做出判断后，立刻指出其已经关注和遗漏的线索；二是让用户在新的信息中再次使用同一种方法，而不是只读完一段解释。基于这一洞察，Insight AI 从单轮问答转向“真实问题处理 + 引导训练 + 能力回顾”的产品结构。

方案设计

产品提供三个入口。快速判断允许用户粘贴真实遇到的健康说法，获得来源核查、证据分级、推理拆解和下一步验证建议；引导训练提供经过风险控制的健康信息微情境，让用户先判断可信度并说明依据，再圈定可疑线索，随后获得即时反馈，完成改写、反驳或验证路径选择，最后用一则新情境检查是否真正掌握方法；能力回顾汇总用户近期容易忽略的判断维度，并推荐下一次练习。一次完整训练遵循“首次判断 → 说明依据 → 识别薄弱点 → 微情境练习 → 即时反馈 → 新情境应用 → 更新画像与复习建议”的闭环。后台由 Understanding、Retrieval、Reasoning、Reflection 四层 Agent 能力支撑，但用户看到的是连贯的任务和反馈，而不是复杂的技术步骤。

落地推进

MVP 先聚焦一条最短可用链路：输入健康说法 → 用户给出初步判断与信心 → Agent 检索可信资料 → 展示证据与推理问题 → 用户完成一则迁移练习 → 收集反馈。首版覆盖快速判断、依据解释、微情境训练和基础薄弱点记录；能力趋势、自动复习和跨领域扩展放到后续版本。工作流使用 LangChain 编排，通过 Prompt Engineering 控制提问、提示和反馈结构，Chroma 与 DashScope Embedding 负责知识召回，FastAPI 与 React 承载服务和交互；Coze 用于快速验证部分流程。RAG 的作用不是替用户做决定，而是为每次反馈提供可追溯的健康资料。

效果复盘

当前已完成产品定位、目标用户与任务拆解、三种产品模式、核心使用闭环、五类判断维度、四层 Agent 能力和 RAG 证据链路，并形成可继续验证的原型方案。下一步产品效果验证将比较个性化训练、普通 AI 回答和无引导三种体验，观察用户是否判断得更准、能否说清依据、是否更谨慎分享，以及能否在新情境中继续使用学到的方法。项目仍在进行中，页面不提前宣称这些效果已经成立。

迭代反思

当前产品仍有三个需要继续打磨的地方。第一，薄弱点画像主要来自显式选择和回答，后续应结合真实使用行为动态更新，减少填写负担；第二，训练路径目前以规则匹配为主，后续可根据用户表现自动调整难度、提示强度和题目类型；第三，只看一次练习后的答对情况并不足够，还需要通过短时复习和延迟回顾了解方法是否真正保留下来。产品化节奏上，我会先把健康信息的“快速判断 + 依据解释 + 一次练习”做顺，再逐步加入能力回顾、主动复习，以及浏览器和社交信息场景。
